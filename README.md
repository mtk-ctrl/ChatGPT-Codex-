## 掲載方針

OpenAI公式サイトとOpenAI関係者本人のX原投稿だけを情報源として、Work・Codexの利用枠に関する臨時リセットを記録する。閲覧できる原投稿はXのURLを添え、原投稿の検索表示だけで確認した記録には「全文未確認」と明記する。

公式記事に日付しかない場合は日付だけを表示し、実施時刻は補完しない。Xの投稿日時は投稿IDから算出し、日本時間で表示する。投稿時刻と実際の反映時刻は異なり得る。実施予告・完了報告・リセットチケット配布を区別する。

## 公開時の表記基準

- 「臨時リセット」は発表で対象とされたプラン・機能だけを指す。ChatGPT利用者全員を意味しない。
- 投稿1件ごとに履歴を掲載し、予告と実施報告は別記録とする。掲載件数を実施回数として案内しない。
- データ上の`products`は大まかな分類であり個別投稿の対象サービスの証明ではないため、根拠のない対象ラベルは表示しない。
- Xの投稿時刻は日本時間。OpenAI公式の日付だけの記載は日本時間に変換しない。
- RSS・CSVにも予告と実施の違いを残す。

## カレンダーの実施状態の意味（2026-10-24改善）

「リセット発表」は予定や実施の案内が一次投稿で確認された日。リセットの完了を明示した発表がまだ見つからないからといって、未実施という意味ではない。従来の灰色の「予告」を、青枠の「リセット発表」に変更し、青塗りの完了報告と同程度に目立つようにした。チケット予告は別の「配布予告」。公開した事実のstateは変更しない。閲覧者が最近の発表に直行できるようカレンダー初期選択を最新のリセット関連投稿に変更。

OpenAI公式ヘルプ https://help.openai.com/en/articles/20001498-how-resets-work-in-codex では、自動リセットの適用は個人のリセット履歴に出ず、使用状況の変化だけではどの臨時リセットか特定できないと説明。Aboutに出典と制約を記載し、サイトでは各利用者の反映完了時刻を推定していない。

## 一般読者向けの表記ルール（2026-10-26）

- 初めて訪れた人が説明なしで理解できる日本語を使う。内部用語・曖昧な見出し（例：「元の投稿」「元の発表」「原投稿」）はUIで使わない。
- リンクは行き先が分かる動詞付きの名称にする（例：「Xの投稿を見る」「公式発表を見る」）。「詳しく見る」は複数種類のリンクを束ねる表の見出しだけに用いる。
- 日付は日本時間か米国太平洋時間か明記する。「発表があった日」と「実際に利用枠が回復した日」を混同しない。
- 「リセット」は予告を含むこと、チケットは別物であることを見える位置で短く説明する。
- 初見の閲覧者が知りたい順番（いつ・何が・根拠・予想）で構成し、専門的な計算や運用事情は詳細ページへ移す。
- 文言変更時は `scripts/site.py` と `docs/assets/app.js` を確認し、HTML再生成・GitHub Pages公開後の実サイト表示まで検証する。古い `docs/*.html` が残ることがあるのでソース修正のみを完了としない。
